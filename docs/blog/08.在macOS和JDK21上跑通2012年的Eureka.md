# 2026 年了，在 macOS + JDK 21 上跑通 2012 年的 Eureka

> 本文是《Eureka 源码深度解析》系列第 8 篇。前面七篇都是"读"，这一篇是"跑"——
> 把分析过的每一个机制用真实运行验证一遍。读源码不跑代码，等于纸上谈兵。

## 挑战

Netflix Eureka 1.x 是什么年代的项目？

- 构建要求 **JDK 8**（README 还说源码兼容 1.7）
- Servlet 2.5 + Jersey 1.19 + war 包部署
- 我手头：macOS (Apple Silicon) + JDK 21

中间隔着十几年的工具链演进。能跑起来吗？结论先行：**能，而且全部测试通过。**

## 第一关：编译

```bash
./gradlew :eureka-core:compileJava
```

直接报错：

```
Could not resolve com.netflix.nebula:nebula-oss-publishing-plugin:3.6.0
> The server may not support the client's requested TLS protocol versions
```

这不是版本问题，是网络问题——国内访问 plugins.gradle.org 的 TLS 握手不稳定。

**解法**：阿里云镜像。但不要改仓库里的 build.gradle（保持和上游一致），
用 Gradle 的 init script 机制从外部注入：

```bash
cat > /tmp/eureka-init.gradle << 'SCRIPT'
settingsEvaluated { settings ->
    settings.pluginManagement {
        repositories {
            maven { url 'https://maven.aliyun.com/repository/gradle-plugin' }
            maven { url 'https://maven.aliyun.com/repository/public' }
            gradlePluginPortal()
        }
    }
}
allprojects {
    repositories {
        maven { url 'https://maven.aliyun.com/repository/public' }
        mavenCentral()
    }
}
SCRIPT

./gradlew -I /tmp/eureka-init.gradle :eureka-core:compileJava :eureka-client:compileJava
```

结果：**BUILD SUCCESSFUL in 55s**。

JDK 21 编译 target 1.8 的代码只会警告"源值 8 已过时"，不会报错。
仓库自带的 Gradle Wrapper 是 8.14.3（够新），这是能成功的关键——
如果是老版本 Gradle（5.x/6.x），它们不支持 JDK 21，那才是真正的死局。

## 第二关：构建 war

```bash
./gradlew -I /tmp/eureka-init.gradle :eureka-server:war -x test
# BUILD SUCCESSFUL in 6s
# 产物: eureka-server/build/libs/eureka-server-0.0.1-SNAPSHOT.war (22MB)
```

没有任何坑，war 直接出来了。

## 第三关：跑起来

war 需要 Servlet 容器。装 Tomcat？太重。
我发现了一条更聪明的路：**仓库自带的集成测试就会启动真实的服务器。**

`EurekaClientServerRestIntegrationTest` 这个测试类做的事：

```java
private static void startServer() throws Exception {
    File warFile = findWar();              // 找到刚构建的war
    server = new Server(8080);             // 启动嵌入式Jetty
    WebAppContext webapp = new WebAppContext();
    webapp.setWar(warFile.getAbsolutePath());
    server.setHandler(webapp);
    server.start();                         // 真实的Eureka Server跑起来了
}
```

然后用真实的 HTTP 客户端对它做端到端测试：注册、心跳、下线、批量复制……

```bash
./gradlew -I /tmp/eureka-init.gradle :eureka-server:test \
  --tests "com.netflix.eureka.resources.EurekaClientServerRestIntegrationTest"
```

## 第四关：端口冲突

第一次跑，失败：

```
EurekaClientServerRestIntegrationTest > classMethod FAILED
    java.net.BindException at EurekaClientServerRestIntegrationTest.java:244
```

测试硬编码了 8080 端口，我本机被别的程序占着。

**解法**：临时改端口跑完再还原（macOS 的 sed 注意要加 -i ''）：

```bash
sed -i '' 's/:8080/:18080/g; s/Server(8080)/Server(18080)/; s/"8080"/"18080"/' \
  eureka-server/src/test/java/com/netflix/eureka/resources/EurekaClientServerRestIntegrationTest.java
```

## 给想动手的你

完整步骤：clone 仓库 → 创建上文的镜像 init 脚本 → 构建 war →
（如果 8080 被占用）临时改测试端口 → 跑集成测试。
五分钟内可以复现，详细命令都在上文。

## 一句话总结

老项目 ≠ 跑不起来。关键三件套：仓库自带的新版 Gradle Wrapper、镜像 init script、
以及善用项目自带的集成测试当"启动器"。读源码的最后一步永远应该是让它跑起来。
